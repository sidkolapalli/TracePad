# Tracepad community code of conduct

Tracepad welcomes people learning Python, preparing for interviews, and improving the tools around that work. Experience levels and backgrounds will differ. Help make this a place where people can ask questions, make mistakes, and contribute without being mistreated.

## How we work together

- Be respectful and constructive. Discuss the code, evidence, or behavior rather than attacking the person.
- Explain assumptions, give actionable feedback, and accept reasonable corrections. Allow room for beginners and different approaches.
- Respect privacy and boundaries. Ask before sharing someone else's messages, personal details, code, or interview material.
- Do not harass, threaten, discriminate, use sexualized abuse, publish private information without permission, spam, or repeatedly disrupt discussions.

These expectations apply in this repository's issues, pull requests, discussions, and other project-managed spaces, and when someone explicitly represents Tracepad elsewhere. Disagreement and criticism are welcome when expressed respectfully.

## Reporting a concern

For behavior that violates GitHub's policies, use [GitHub's abuse-reporting tools](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam), such as **Block or Report → Report abuse** on a user's profile. A report sent to GitHub Support is handled by GitHub, not automatically delivered to Tracepad's maintainer. GitHub's process and privacy rules apply.

A dedicated private project contact has not yet been published. To request one from the maintainer, open an [issue](https://github.com/sidkolapalli/TracePad/issues) titled **Private contact requested**, without incident details, names, screenshots, or personal information. The request itself is public. Wait for the maintainer to establish a private route before sharing details; you do not need to disclose the incident publicly. There is no guaranteed response time during this alpha.

Security vulnerabilities have a separate [private reporting process](SECURITY.md). Do not use security advisories for conduct reports.

## Maintainer response

The maintainer, [@sidkolapalli](https://github.com/sidkolapalli), is responsible for applying this policy fairly and considering context. Responses may include asking for a change in behavior, removing disruptive content, closing or locking a discussion, restricting participation, or blocking a participant. Serious or repeated harm may warrant immediate restrictions.

Share only the information needed to review a concern. The maintainer should handle reports discreetly and explain decisions to the people involved when appropriate, but cannot promise absolute confidentiality. Requests to reconsider a project decision can use the same private-contact process. Concerns about the maintainer's own conduct can be reported to GitHub when they involve GitHub-policy violations; this small project has no independent internal review panel.
